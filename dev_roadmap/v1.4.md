# ExamOps — 项目开发路线规划 V1.4

**项目名称：** ExamOps  
**项目定位：** 基于个人学习资料的 AI 智能复习桌面软件  
**目标平台：** Windows 10/11  
**运行方式：** 单用户、本地独立应用  
**开发阶段：** 基础架构设计与功能开发规划  
**参考项目：** [Universal ExamPrep Skill](https://github.com/ZeKaiNie/universal-examprep-skill)

---

## 一、项目总体目标

ExamOps 是一款面向大学生的 AI 智能学习与期末复习软件。

用户可以将教材、PPT、PDF、Word 等学习资料导入软件，并自行配置 AI 模型接口。

系统通过解析用户提供的资料，帮助学生理解知识点、开展章节学习、进行小测验，并根据学习表现安排后续复习。

与传统刷题软件不同，ExamOps 不以题库为核心，而是以**自主学习路径、AI 个性化教学、知识巩固和学习状态管理**为核心。

### 核心使用流程

1. 创建课程。
2. 导入教材、PPT 等资料。
3. 配置自己的 AI 模型。
4. 自动识别章节与知识点。
5. 创建或调整个人学习路径。
6. 按照路径完成学习任务。
7. 通过 AI 小测检验掌握情况。
8. 记录薄弱知识点并安排复习。
9. 下次启动时继续之前的学习。

## 二、固定技术架构

### 2.1 基础技术选型

| 模块 | 技术 |
|---|---|
| 桌面框架 | Tauri 2 |
| 前端 | Vue 3 + TypeScript |
| UI | Tailwind CSS 4 |
| 状态管理 | Pinia |
| 原生业务层 | Rust |
| 文档解析 | Python Sidecar |
| 数据库 | SQLite |
| 全文检索 | SQLite FTS5 |
| AI 通信 | 自定义 API / OpenAI Compatible |
| Windows 打包 | Tauri + NSIS |

Python Sidecar 用于复杂文档解析，由 Tauri 自动启动和管理，无需用户额外安装 Python。

### 2.2 不可变更的项目约束

- 始终为单用户本地软件。
- 使用独立 Windows 桌面应用，不以浏览器作为入口。
- 不使用云服务器、云数据库或云存储。
- 不开发账号注册和登录系统。
- 不开发多人协作和局域网访问功能。
- 用户文件及学习数据默认保存在本机。
- AI 模型由用户自行配置。
- 仅 AI API 调用等用户主动发起的外部操作需要联网。
- 不强制使用题库或 Embedding 模型。
- 安装包应包含所需运行环境。

## 三、核心功能模块

### 1. Document Engine — 文档引擎

负责：

- 导入 PDF、PPTX、DOCX、TXT、Markdown。
- 提取教材文字。
- 自动识别章节。
- 提取文档图片。
- 保留原文页码及位置。
- 对内容进行分块和建立检索索引。

### 2. Context Engine — 上下文引擎

采用全文上下文与 RAG 混合架构：

- Full Context：完整读取适合上下文窗口的资料。
- RAG：从教材中检索相关知识。
- Auto：根据任务、模型容量和资料规模自动选择。

第一版使用 SQLite FTS5，后续扩展向量语义检索。

### 3. Tutor Engine — AI 教学引擎

支持三种主要学习模式：

- 从零学习：AI 按章节逐步讲解。
- 正常复习：针对已有知识进行回忆、理解和巩固。
- 考前冲刺：根据考试时间和知识薄弱程度调整复习重点。

支持随时追问、解释概念、举例、跳过及切换章节。

AI 回答需要区分教材依据、AI 补充和自行推导，并提供可验证的来源引用。

### 4. Learning Path Engine — 学习路径引擎

允许学生自由创建复习路线。

学习步骤可以包含：

- 阅读教材。
- 阅读 PPT。
- 观看外部网课。
- AI 讲解。
- 知识点小测。
- 主动回忆。
- 复习旧知识。
- 自定义学习任务。

支持 AI 推荐路径、完全手动编排及混合模式。

允许用户调整步骤顺序、增加或删除步骤。

视频课程以外部链接、时间戳和用户笔记的形式管理。不内嵌视频网站，也不依赖浏览器组件实现学习功能。

AI 若需根据视频内容讲解或出题，应使用用户提供的字幕、文字稿或笔记，不能仅凭视频链接推断内容。

### 5. Assessment Engine — 小测引擎

小测是核心学习功能，但大型题库系统不是第一版的必要条件。

支持：

- 选择题。
- 判断题。
- 简答题。
- 自由复述。
- AI 情景应用题。

用户可以设置：

- 每个知识点后进行小测。
- 每个章节后进行小测。
- 仅手动触发小测。
- 小测题目数量。
- 是否允许跳过。

小测结果需要关联具体知识点，为后续复习提供依据。

### 6. Study State Engine — 学习状态引擎

记录：

- 当前学习课程。
- 当前知识点。
- 学习路径进度。
- 已完成学习任务。
- 历史小测表现。
- 疑难点及错题。
- 知识掌握情况。
- 下次建议复习时间。

必须区分“学过”和“已掌握”。

软件重新启动后，应恢复用户上一次学习的位置和记录。

### 7. Model Gateway — AI 模型适配层

负责：

- 用户自定义 API。
- 多模型配置管理。
- API 连接测试。
- 流式响应。
- 模型参数管理。
- Token 预算控制。
- 错误处理与请求取消。

模型不能直接修改数据库或执行本地系统命令。

## 四、项目开发阶段

建议采用六个阶段推进，优先完成可运行的最小版本，再增加高级功能。

### Stage 1 — 基础架构搭建

**目标：建立可以独立运行的桌面软件。**

开发内容：

1. 初始化 Tauri 2 + Vue 3 项目。
2. 配置 TypeScript、Tailwind CSS 和 Pinia。
3. 搭建基础 UI、导航和设置页面。
4. 集成 SQLite 数据库。
5. 建立数据库 Migration 机制。
6. 验证 Python Sidecar 运行和通信。
7. 实现基础课程管理。

**验收：** 可以安装、启动 ExamOps，创建课程并持久化保存数据。

### Stage 2 — 文档处理与检索

**目标：让软件能够理解用户导入的学习资料。**

开发内容：

1. 实现文档导入。
2. 集成 PDF、PPTX、DOCX 解析。
3. 自动识别教材章节。
4. 提取文本及图片。
5. 保存原文页码信息。
6. 建立 SQLite FTS5 索引。
7. 实现关键词检索。
8. 开发资料阅读和预览界面。

**验收：** 可以导入一份教材，识别章节并准确检索、定位原文。

### Stage 3 — AI 接口与上下文引擎

**目标：让用户能够基于自己的资料与 AI 交互。**

开发内容：

1. BYOK 模型配置。
2. API 连接测试。
3. AI 流式对话。
4. 全文上下文模式。
5. RAG 关键词检索模式。
6. Auto 上下文自动路由。
7. AI 回答来源标记。
8. 会话记录持久化。

**验收：** 用户可配置 AI，对导入教材进行问答，并查看回答对应的资料来源。

### Stage 4 — AI 教学与自定义路径

**目标：形成完整的学习流程。**

开发内容：

1. AI 分章节教学。
2. 知识点提取与管理。
3. 自定义学习路径。
4. 路径步骤排序、删除和修改。
5. 学习资料与网课资源关联。
6. 学习任务完成状态。
7. AI 讲解、追问和跳转机制。
8. 进度保存及恢复。

**验收：** 用户可以创建包含教材、网课、AI 教学的学习路径，并按自己的节奏完成学习。

### Stage 5 — 小测与复习调度

**目标：形成有效的知识巩固闭环。**

开发内容：

1. AI 生成知识点小测。
2. 客观题自动判分。
3. 简答题 AI 辅助反馈。
4. 用户答案及小测记录保存。
5. 知识点掌握状态评估。
6. 薄弱知识点追踪。
7. 间隔复习调度。
8. AI 推荐下一步复习内容。

**验收：** 系统能够依据学习资料生成小测，记录用户表现，并为掌握不充分的知识安排后续复习。

### Stage 6 — 集成、测试与发布

**目标：完成可交付的 Windows 软件。**

开发内容：

1. 统一界面设计。
2. 完成所有模块集成。
3. 修复稳定性问题。
4. 测试异常文件、API 错误和网络中断。
5. 进行本地数据持久化测试。
6. 处理第三方依赖及许可证。
7. 构建 Windows 安装包。
8. 编写安装说明和使用文档。

**验收：** 用户无需配置开发环境，安装软件后即可独立使用核心功能。

## 五、推荐团队分工

以四人开发团队为例：

| 负责人 | 主要职责 |
|---|---|
| A：前端开发 | Vue 页面、UI、课程界面、学习路径编辑器 |
| B：原生后端 | Rust、Tauri、SQLite、数据持久化 |
| C：AI 与检索 | Model Gateway、Context Engine、Tutor Engine |
| D：文档及测试 | Python 文档解析、小测逻辑、测试和打包 |

每名成员负责的模块需提供接口说明及最基本的测试。

具体工作可以并行，但必须统一数据结构和通信协议。

## 九、最终产品体验

ExamOps 希望实现以下完整使用场景：

用户导入一门课程的教材和 PPT，然后自行添加正在观看的网课，将其与对应章节关联。

用户可以选择由 AI 自动生成学习计划，也可以完全自行安排学习顺序。

例如：

**观看网课 → 阅读 PPT → AI 解释 → 知识点小测 → 巩固薄弱知识 → 继续下一章节**

AI 会根据用户导入的课程资料进行讲解，尽可能提供准确的教材引用。

每次小测结束，软件记录学习表现，并据此建议复习薄弱知识点。

用户可以随时修改学习路径，系统不会强迫用户遵循固定教学步骤。

当用户下次打开 ExamOps 时，可以继续之前的学习，并看到需要复习的内容。

### 项目最终定位

**ExamOps 不是传统题库软件，也不是简单的 AI 聊天工具，而是一款以学生自主学习路径为中心、结合 AI 教学与知识巩固机制的本地智能复习软件。**

软件的核心价值是让学生能够根据自己的学习习惯组织资源，在 AI 辅助下持续学习、主动回忆、检验知识，并逐渐改善对课程内容的掌握程度。

**项目开发总路线：**

基础架构 → 文档解析 → AI 问答与混合检索 → 自定义学习路径 → AI 教学 → 知识点小测 → 复习调度 → 集成与交付。
